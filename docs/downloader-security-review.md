# TikTok Video Downloader Security Review

## Scope

This review covers the public preview endpoint, URL intake, request limiting,
media-byte validation, temporary filesystem storage, cleanup, and the downloader
interface.

The current release validates and previews TikTok video identity. Media delivery
remains disabled until a verified upstream provider can return bytes without
introducing an arbitrary-fetch or access-control bypass.

## Security boundaries

- Only full HTTPS TikTok video URLs are accepted.
- Hostnames must be `tiktok.com` or a subdomain validated by the shared Tool
  Engine.
- Profile pages, short URLs, non-video paths, URL credentials, ports, and
  non-TikTok domains are rejected.
- Preview requests require an explicit rights confirmation.
- Cross-origin browser preview requests are rejected.
- JSON request bodies are limited to 4 KB.
- Preview responses use `Cache-Control: no-store`.

## Abuse controls

- Production rate limiting uses Upstash Redis when
  `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` are configured.
- The fallback limiter is process-local and is intended only for local
  development.
- Client network identifiers are HMAC-hashed with an ephemeral process salt
  before they are used as rate-limit keys.
- The preview endpoint returns limit, remaining, reset, and retry headers.

## Media-file controls

- Only `video/mp4` is accepted.
- The declared content length must match the received byte length.
- Files larger than 100 MB are rejected before storage.
- MP4 bytes must contain an `ftyp` signature.
- A SHA-256 checksum is recorded and verified before one-time delivery.
- Temporary filenames are random UUIDs generated by the server.
- Files and metadata are written with owner-only permissions.
- Token format and resolved paths are checked to prevent path traversal.

## Retention and cleanup

- User media is never written to permanent application storage.
- Temporary media has a maximum application retention of 15 minutes.
- Expired media and metadata are deleted during cleanup passes.
- Successful delivery consumes and deletes both temporary files.
- Preview validation does not create a media file.

## Verification

- Unit tests cover URL allowlisting, HTTPS enforcement, input type detection,
  MIME validation, MP4 signatures, file sizes, rate-limit windows, path
  traversal, expiration cleanup, integrity checks, and one-time consumption.
- API checks cover rights confirmation, cross-origin rejection, `429` rate
  limiting, retry headers, and empty temporary storage after preview.
- Browser checks cover valid preview, invalid-domain errors, FAQ behavior,
  responsive layout, and console errors.

## Production prerequisites

The following are release blockers for enabling the download button:

1. Configure Upstash credentials so limits are distributed across Vercel
   instances.
2. Use a verified media provider with a separate outbound host allowlist.
3. Reject redirects to unapproved hosts and private, loopback, link-local, or
   reserved network ranges.
4. Stream provider bytes through the existing file validator before temporary
   storage.
5. Keep delivery one-time and retain the 15-minute application cleanup policy.
6. Add provider-specific copyright, removal, and regional-availability handling.
